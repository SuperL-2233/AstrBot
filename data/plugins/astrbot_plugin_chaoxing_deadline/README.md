# astrbot_plugin_chaoxing_deadline

独立的超星学习通只读同步、任务查询、截止查询和 QQ 提醒插件。

## 能力

- 使用 `SuperL-2233/chaoxing-api` 提交 `554e01a` 已验证的只读登录和读取流程。
- 同步作业、视频/限时章节和讨论到插件独立的 SQLite 数据库。
- 按待办、已完成或全部状态查询作业、视频章节和讨论缓存记录。
- 查询未来若干天内有明确截止时间的待办任务。
- 每次查询作业、视频/限时章节、讨论或截止日期前检查缓存；最近成功同步超过 24 小时或从未同步时，先尝试云端刷新。
- 每次云端刷新成功后遍历所有未完成且有明确截止时间的项目，同步持久化提醒计划。
- 默认在截止前 3 天、2 天、1 天、12 小时和 1 小时去重推送到绑定的 QQ 私聊。
- 新发现任务、恢复绑定或重启后，若已错过提醒时间但任务尚未截止，只补发最近一个阶段，并显示实际剩余时间。
- 可按任务取消或恢复提醒跟踪；忽略状态跨云端刷新保留。
- 单门课程局部失败不会阻断其他课程；全部课程主页失败时保留旧缓存。
- 启动或热重载时只检查缓存新鲜度，不会无条件访问云端；SQLite 同步租约阻止多个插件实例重复抓取。
- 一旦识别到超星 `antispiderShowMsg` 反爬页，立即停止当前批次，并默认进入持久化 12 小时冷却期。

普通视频和多数讨论可能没有独立截止时间。插件会显示“平台未提供明确截止时间”，且不会为这些条目编造或推送截止提醒。

“已完成”只依据学习通页面明确返回的完成、提交或批阅状态；“已截止/已结束”不会被误算为完成。讨论列表通常不返回当前用户是否参与过，因此已完成讨论只会包含来源明确标记为完成的记录，插件不会根据发布时间或截止时间猜测。

## 配置与使用

在 AstrBot 插件配置中设置 `enabled`、`phone` 和 `password`。插件不要求配置 QQ ID：查询命令可直接使用；提醒绑定和解绑必须在私聊执行，提醒目标就是最近执行绑定命令的私聊。手机号、密码、Cookie、动态课程令牌、SQLite 数据库和 QQ 会话目标都属于运行时私密数据，不应提交到 Git。

当前只保存一个提醒目标，因此新的私聊绑定会覆盖旧目标。若机器人对多人开放，请使用 AstrBot 平台或会话权限限制谁能执行插件命令。

天气推送和超星提醒分别保存接收目标。即使天气已能发送到 QQ，也需要在接收超星提醒的 QQ 私聊中执行 `/超星提醒绑定`。两者都通过 AstrBot 的 `Context.send_message` 主动推送。

升级时，原来的标准配置 `[168, 120, 72, 24, 5, 2, 1]` 会自动按新的五阶段配置生效，并清理旧的待发送阶段；其他自定义阶段保持原值。`/超星状态` 显示实际生效的提醒阶段、扫描任务状态、待推送数量和下次计划时间。截止时间默认按 `Asia/Shanghai` 解释，可通过 `timezone` 配置调整，不受服务器系统时区影响。

默认缓存有效期为 24 小时。过期查询会尝试刷新，但刷新失败不会删除旧缓存；查询结果会明确说明自动刷新失败并继续返回已有数据。`/超星同步` 和 `sync_chaoxing_tasks` 可请求立即同步。在线同步必须启用且凭据完整，自动刷新才会访问云端；反爬冷却或已有同步租约生效时，手动命令和工具也只返回状态，不发出请求。

插件在同一生命周期内复用登录会话，降低重复登录频率。同步使用默认 30 分钟的跨实例租约；插件卸载或热重载时会等待已进入工作线程的请求退出后再释放租约，避免旧实例与新实例重叠访问。`/超星状态` 会显示租约和反爬冷却状态。

提醒扫描与云端同步是两个独立循环。提醒计划每 5 分钟扫描一次，因此不会受默认 120 分钟云端刷新间隔限制。每次扫描先根据本地缓存重建计划，保留未来阶段并补发最近一个已到期阶段，避免停机后一次发送多条过时提醒。提醒覆盖作业、视频、限时章节和讨论，只要来源给出明确截止时间且状态仍为未完成。完成、忽略、过期、删除或截止时间变更的项目会撤销不再适用的后续提醒；完成状态以最近一次成功同步的缓存为准。发送失败、适配器未就绪或插件卸载时取消的发送不会记作成功，可在后续扫描重试。

启用后先在所有者 QQ 私聊中执行：

```text
/超星同步
/超星提醒绑定
```

查询命令：

```text
/超星任务 全部
/超星任务 作业
/超星任务 视频 课程关键词
/超星任务 讨论
/超星已完成 作业
/超星已完成 视频
/超星已完成 讨论
/超星全部 全部
/超星截止 7
/超星忽略 选做作业名称
/超星恢复 选做作业名称
/超星状态
```

本插件只读取数据，不提交作业、不发布讨论、不播放视频，也不写入学习进度。请遵守学校规定和超星平台条款，并控制同步频率。

## LLM tools

- `get_chaoxing_tasks`：统一按类型（`作业`、`视频`、`限时章节`、`讨论`，留空查全部）、状态（`待办`、`已完成`、`全部`）和关键词查询。
- `get_chaoxing_deadlines`：查询指定天数内的明确截止任务。
- `sync_chaoxing_tasks`：立即从云端同步全部支持的项目，并重建提醒计划。
- `set_chaoxing_task_tracking`：按 `task_key` 或唯一关键词取消/恢复某个项目的提醒；歧义匹配只返回候选项，不会批量修改。

原来三个分类查询工具已合并到 `get_chaoxing_tasks`，分类查询能力保留。若人格配置曾单独选择旧分类工具，请改为选择统一查询工具。

LLM 查询结果保留任务标识、课程、类型、标题、状态、截止时间以及非空的开始时间、链接和备注；不返回内部课程/班级 ID 和每行重复的来源字段。缓存新鲜度统一放在 `cache` 中，刷新失败保留错误码和原因。命令、同步存储和提醒计划继续使用完整服务数据。

全局 `get_plugin_status` 由独立的 `astrbot_plugin_capability_registry` 提供，本插件只通过公开协议声明自己的能力和状态。
