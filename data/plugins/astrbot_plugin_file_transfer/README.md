# 私人文件快传管理插件

该插件管理独立文件快传服务的授权和存储清单，不处理上传和下载字节，不在机器人进程中存储文件，也不依赖校园助手插件。

## 部署和配置

先部署同级独立仓库 `file-transfer/` 中的服务，按其 README 配置 HTTPS 和内部网络。

在 AstrBot 插件配置中设置：

- `enabled=true`
- `owner_qq_id`：唯一所有者的实际发送者 ID，QQ 官方机器人使用其返回的 openid。
- `admin_url`：原生同机部署为 `http://127.0.0.1:8788`；使用服务仓库的 Compose 网络覆盖文件时为 `http://file-transfer:8788`。
- `admin_token`：文件服务 `FT_ADMIN_TOKEN` 的值，至少 32 字符。

未配置所有者时关闭管理。所有命令和授权工具都要求所有者私聊，包括状态与列表。管理密钥只放入忽略的运行配置，不能转发给访客、输出到日志或提交到 Git。

## 命令

```text
/快传授权 [整批额度] [保留分钟]
/快传授权
/快传授权 5G 60
/快传列表
/快传文件 [页码]
/快传删除 <完整文件ID>
/快传撤销 <完整批次ID>
/快传状态
/快传帮助
```

默认整批 2GB、提交后保留 30 分钟，最大整批 10GB。GB 为十进制。通行密钥生成后 1 小时内兑换，兑换后上传窗口固定 30 分钟。额度与保留时间在签发时固定，不提供续期接口。撤销整批会中止正在传输的文件并清理。

`/快传列表` 查询批次；`/快传文件` 查询全部批次中的实际文件清单，默认第 1 页，每页 10 个。使用 `/快传文件 2` 查看下一页。清单显示文件名、完整文件 ID、批次 ID、状态、已接收/声明大小和截止时间；汇总为全部文件的真实清单数量，不是当页条数。仅列出快传存储目录管理的文件，不浏览服务器其他挂载目录。

从清单复制完整文件 ID 后，发送 `/快传删除 <文件ID>` 删除单个文件。它会停止该文件正在进行的上传或下载，删除磁盘文件并释放清单额度，保留同批其他文件和原计时。整批删除继续使用 `/快传撤销 <批次ID>`。删除失败会明确报错；文件保持不可访问并由服务重试清理，不返回虚假的成功提示。文件名、显示序号和不完整 ID 不能代替完整文件 ID。

文件管理要求插件与独立服务均升级到 0.2.0。独立服务启动时自动迁移旧清单；既有文件、授权和截止时间保留。所有管理命令继续要求已启用插件、已配置的所有者和私聊。没有增加自然语言删除工具，现有自然语言授权工具保持原行为。

只把授权回复中的入口和 `U-` 通行密钥发给上传者。上传者完成提交后获得 `D-` 文件密钥，在网页的同一个输入框里输入即可下载。

## 自然语言授权工具

`create_file_transfer_grant(total_size="2G", retention_minutes=30)` 与 `/快传授权`
共用权限、参数校验和真实授权接口。`total_size` 是整批额度，支持 `500M`、`2G`、`5GB`
等十进制单位，最多 10GB；`retention_minutes` 是提交完成后的保留分钟数，必须是正整数。

在所有者私聊中可以直接说：

- “帮我开一个快传授权。”（默认 2GB、保留 30 分钟）
- “生成一个 5G、保留 60 分钟的快传授权。”

工具返回 JSON，包含 `success` 和 `message`；成功消息含入口、一次性通行密钥、
兑换截止、额度、保留时间和批次 ID。发送者与私聊身份来自 AstrBot 的真实事件，
模型不能通过参数指定所有者。每次调用都会签发一个新授权，失败不会自动重试。
插件更新后重载“私人文件快传”，并确保当前会话的工具列表启用了该工具。

独立服务不可用时明确报错，不生成本地替代密钥。插件仅复用 aiohttp，并在卸载时关闭管理连接；重载或停止机器人不影响文件服务中正在进行的上传、下载和清理。
